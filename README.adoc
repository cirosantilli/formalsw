== Install

Install the cleanxyz Python library:

----
pipx install cleanxyz
----

Install Elan, Lean's version manager. On Linux:

----
curl https://elan.lean-lang.org/elan-init.sh -sSf | sh
----

Installation details for other systems: https://github.com/leanprover/elan

Now test it on a hello world link:tests/pass/range_sum.py[]:

----
cleanxyz tests/pass/range_sum.py
----

and if all went well you should see a message:

----
All 3 checks passed
----

and exit status 0.

== Getting started

Support that you have two alternative implementations of the sum of integers 0 to n, one naive and one optimized:

----
def sum(n: int) -> int:
    if n <= 0:
        return 0
    return (n * (n - 1)) // 2

def sum_naive(n: int) -> int:
    total = 0
    for i in range(n):
        total += i
    return total
----

and then suppose that your goal is to formally prove that for every possible input both functions return the same output, i.e. that the functions are equivalent.

To convey our goal, we have specified on the docstrings which properties we want to prove the functions to have, e.g.:

* `@cleanxyz: NoThrow`: the function `sum` does not throw any exception for any input
* `@cleanxyz: Equiv(sum_naive)`: the function `sum` has the same output for every input

After this is specified, if you run:

----
cleanxyz tmp.py
----

it blows up with:

----
error: tmp.py:4: missing proof file tmp.py.lean for `@cleanxyz: NoThrow`
----

which is good because haven't proven what we said we wanted to prove yet!

To create the required proofs, we must create a tmp.py.lean file containing the following theorems:

----
import «.cleanxyz».tests.pass.«range_sum.py.ast»
import CleanXYZ

namespace Tmp

theorem sum_noThrow (n : Int) :
    ∃ value,
      CleanXYZ.PyAst.evalUnaryIntFunction
          RangeSumAst.module "sum" n =
        some value := by sorry

theorem sumNaive_noThrow (n : Int) :
    ∃ value,
      CleanXYZ.PyAst.evalUnaryIntFunction
          RangeSumAst.module "sum_naive" n =
        some value := by sorry

theorem sum_equiv_sumNaive (n : Int) :
    CleanXYZ.PyAst.evalUnaryIntFunction
        RangeSumAst.module "sum" n =
      CleanXYZ.PyAst.evalUnaryIntFunction
        RangeSumAst.module "sum_naive" n := by sorry

end Tmp
----

And now we can try again:

----
cleanxyz tmp.py
----

but this time it fails with:

----
error: tmp.py.lean:11: proof uses `sorry`
----

because we cheated with `sorry` which tells Lean to skip a proof.

The final passing proof is something like the following ungodly file. I don't expect you to read and understand it.

The beauty of is is, and the entire reason for this project existing, of course, that you don't need to write that by yourself. You can just ask an LLM to do it for you! 

You only need to understand the definition of properties that you care about in the comments of the source code.

Then you let the LLM loose, and so long as the LLM does not touch your .py source files during the proof step, only the .lean ones, the our scripts and the Lean formal system ensures that the property is true.

Here's the file:

----
import «.cleanxyz».«tmp.py.ast»
import CleanXYZ

namespace Tmp

/-- `sum` returns an integer for every integer input. -/
theorem sum_noThrow (n : Int) :
    ∃ value,
      CleanXYZ.PyAst.evalUnaryIntFunction
          TmpAst.module "sum" n =
        some value := by
  by_cases hn : n <= 0
  · refine ⟨0, ?_⟩
    simp [
      CleanXYZ.PyAst.evalUnaryIntFunction,
      CleanXYZ.PyAst.Module.findFunctionBody,
      CleanXYZ.PyAst.findFunctionBodyIn,
      CleanXYZ.PyAst.evalIntBlock,
      CleanXYZ.PyAst.evalBoolExpr,
      CleanXYZ.PyAst.evalIntExpr,
      CleanXYZ.PyAst.Env.get?,
      CleanXYZ.PyAst.evalCmpOp,
      TmpAst.module,
      hn,
    ]
  · refine ⟨CleanXYZ.PyAst.sumRange n.toNat, ?_⟩
    simp [
      CleanXYZ.PyAst.evalUnaryIntFunction,
      CleanXYZ.PyAst.Module.findFunctionBody,
      CleanXYZ.PyAst.findFunctionBodyIn,
      CleanXYZ.PyAst.evalIntBlock,
      CleanXYZ.PyAst.evalBoolExpr,
      CleanXYZ.PyAst.evalIntExpr,
      CleanXYZ.PyAst.Env.get?,
      CleanXYZ.PyAst.evalCmpOp,
      TmpAst.module,
      hn,
    ]

/-- `sum_naive` returns an integer for every integer input. -/
theorem sumNaive_noThrow (n : Int) :
    ∃ value,
      CleanXYZ.PyAst.evalUnaryIntFunction
          TmpAst.module "sum_naive" n =
        some value := by
  refine ⟨CleanXYZ.PyAst.sumRange n.toNat, ?_⟩
  simp [
    CleanXYZ.PyAst.evalUnaryIntFunction,
    CleanXYZ.PyAst.Module.findFunctionBody,
    CleanXYZ.PyAst.findFunctionBodyIn,
    CleanXYZ.PyAst.evalIntBlock,
    CleanXYZ.PyAst.evalIntExpr,
    CleanXYZ.PyAst.evalRangeContribution,
    CleanXYZ.PyAst.Env.get?,
    TmpAst.module,
  ]

/-- `sum` and `sum_naive` give the same result for every integer input. -/
theorem sum_equiv_sumNaive (n : Int) :
    CleanXYZ.PyAst.evalUnaryIntFunction
        TmpAst.module "sum" n =
      CleanXYZ.PyAst.evalUnaryIntFunction
        TmpAst.module "sum_naive" n := by
  by_cases hn : n <= 0
  · simp [
      CleanXYZ.PyAst.evalUnaryIntFunction,
      CleanXYZ.PyAst.Module.findFunctionBody,
      CleanXYZ.PyAst.findFunctionBodyIn,
      CleanXYZ.PyAst.evalIntBlock,
      CleanXYZ.PyAst.evalBoolExpr,
      CleanXYZ.PyAst.evalIntExpr,
      CleanXYZ.PyAst.evalRangeContribution,
      CleanXYZ.PyAst.sumRange,
      CleanXYZ.PyAst.Env.get?,
      CleanXYZ.PyAst.evalCmpOp,
      TmpAst.module,
      hn,
      Int.toNat_of_nonpos hn,
    ]
  · simp [
      CleanXYZ.PyAst.evalUnaryIntFunction,
      CleanXYZ.PyAst.Module.findFunctionBody,
      CleanXYZ.PyAst.findFunctionBodyIn,
      CleanXYZ.PyAst.evalIntBlock,
      CleanXYZ.PyAst.evalBoolExpr,
      CleanXYZ.PyAst.evalIntExpr,
      CleanXYZ.PyAst.evalRangeContribution,
      CleanXYZ.PyAst.Env.get?,
      CleanXYZ.PyAst.evalCmpOp,
      TmpAst.module,
      hn,
    ]

end Tmp
----

and now if you run:

----
cleanxyz tmp.py
----

there's no output, which means that all proofs were verified!

== Further usage

Directories are also accepted; every `.py` file under the directory is checked:

[source,sh]
----
./cleanxyz tests/pass
----

== How it works

The way it all works is as follows. When you run:

----
cleanxyz tmp.py
----

it will determine where to create the `.cleanxyz` directory. When you are inside a .git repository, `.cleanxyz` is always placed next to the `.git`. You basically always  want to use Git becuse you want to check that you LLMs haven't mofidifed your specifications in source files.

Then, inside the `.cleanxyz` directory, `cleanxyz` converts the input Python source code to a versioned JSON AST under `.cleanxyz/tmp.py.ast.json`. This is the language-neutral interchange artifact, so a future converter only needs to produce the same JSON schema.

The adjacent `.cleanxyz/tmp.py.ast.lean` is only a small import bridge. Lean reads the JSON with `include_str`, validates `schema_version`, and elaborates it into a typed `CleanXYZ.PyAst.Module`. Proofs therefore continue to use `TmpAst.module` and operate on the typed data structure, not on untrusted claims made by the converter.

The top-level JSON shape is:

[source,json]
----
{
  "schema_version": 1,
  "ast": {
    "type": "Module",
    "body": []
  }
}
----

Nodes use a `type` discriminator and fields close to Python's `ast` names. For example, a name expression is `{"type": "Name", "id": "n"}` and a constant is `{"type": "Constant", "value": 1}`.

At the same time, cleanxyz searches for `@cleanxyz:` markers in Python docstrings, and when those are found, it dumps them under `.cleanxyz/tmp.py.reqs.lean` in such a way that unless proof of each requirement is also found, things will blow up when Lean runs.

----
example :
    CleanXYZ.Property.Function.NoThrow TmpAst.module "sum"
  := Tmp.sum_noThrow

example :
    CleanXYZ.Property.Function.Equiv TmpAst.module "sum" "sum_naive"
  := Tmp.sum_equiv_sumNaive

example :
    CleanXYZ.Property.Function.NoThrow TmpAst.module "sum_naive"
  := Tmp.sumNaive_noThrow
----

Finally, cleanxyz runs Lean putting everything together:

* `.cleanxyz/tmp.py.ast.json` with the language-neutral AST representation
* `.cleanxyz/tmp.py.ast.lean` with the small JSON-to-Lean import bridge
* `.cleanxyz/tmp.py.reqs.lean` mentioned above with the proof requirements
* `tmp.py.lean` which is supposed to contain your proof
* link:CleanXYZ.lean[] which defines the Python AST representation and properties of the Python language which are then used in correctness proofs
